# 把绘图交给子代理

图形值得做的时候，用 Levin 的 `Agent` 工具起一个 general-purpose worker，角色 `worker`，
把一个描述性的任务名和下面的简报交给它。Creator SDK v3 没有"安装新 agent 类型"的能力，所以
**不要**假设存在 `scientific-visualization` 类型或自动完成钩子。只有在父级已经判断过
"做图有用" 之后才委派；没有可测结果的小失败任务不需要委派。

## 交给 worker 的简报

你负责这次实验的科学制图。父级负责结论与验收。只读完成这些图所需的列、manifest 片段和方法，
从实验目的与想支持的推断出发，不要从风格出发。

父级需提供：绝对工作区；实验 id；数据集工件 id 与路径；已核实的 SHA-256（或明确写下的核实
局限）；原始复本 id；单位；实验条件；图的预期用途；归你使用的输出目录。数据、单位、配对或
来源有任何含糊，**把这个阻塞点返回**，不要猜。

1. 确认输入与已登记证据一致。绝不修改输入文件、未经许可查远程数据、或使用未经核实的手抄值。
2. 完整绘图脚本留在实验的 `scripts/` 下，所有中间产物留在
   `levin_scratch/<task_id>/<agent_id>/`，绘图/字体缓存也放这里。
3. 该显示单个复本的地方就显示。区分技术重复与生物学重复，标注单位，说明估计量、不确定度定义、
   n 与缺失值处理规则。不要编造推断统计、不要合并不可比条件、不要暗示因果。
4. 刻度可读、坐标轴诚实。对数轴必须显式说明。避免装饰和不必要的 3D。有可用的科学绘图技能就去读。
5. 导出 SVG 或 PDF 矢量 + PNG 栅格（一般 300 dpi）。报告字体嵌入情况与栅格限制。图要嵌进 PDF
   时必须同时给一份栅格件。
6. 用 `research_record_register_run` 记下确切命令、参数、有效随机种子（若随机）、软件版本与
   数据集引用。脚本和图用带 `input_ids`、`script_id`、`run_id` 的方式登记，再回头更新 run 的
   输出工件 id。
7. 核对数值、标签、单位与文件是否真的存在。只有在真的能看图时才检查渲染效果；否则如实报告
   "尚未做视觉核查"。
8. 只回传脚本/图工件 id 与路径、简短发现、已知局限，以及需要父级做的科学取舍。不要回传完整
   数据集或日志。

父级核实证据、决定图接受与否，并自己填 `reviewed_by`。**这些都不能由 worker 代填。**
